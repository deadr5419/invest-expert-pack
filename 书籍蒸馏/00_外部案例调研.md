# 书籍蒸馏 · 外部案例调研（启动前差缺补漏）

> 调研时间：2026-08-16 · 目的：为 v2 方案找外部参照，识别可吸收的增量
> 结论先行：**方案主体路线被外部案例验证，无需推翻；建议吸收 3 项增量（见文末），均待用户拍板后回写主库**

## 案例清单与必要性分析

### 1. 仓颉.Skill（cangjie-skill）——最直接对标 ★★★★★
**是什么**：开源"书籍→AI Skill"蒸馏 SOP（github.com/kangarooking/cangjie-skill），**已有投资书籍实践**：巴菲特致股东的信（20个skill）、穷查理宝典（12）、段永平投资问答录（15）。

**核心机制**（六阶段）：Adler《如何阅读一本书》整书理解 → 5 Agent 并行提取（思维框架/原则/作者案例/**反面教训**/概念词典）→ **三重验证筛选**（跨域验证：书中≥2个独立场景出现；预测力测试：能推导书外问题；独特性检验：非常识——**通过率仅 25–50%**）→ RIA++ 构造（触发条件+边界+可执行步骤）→ Zettelkasten 链接 → 压力测试（诱饵测试：不该触发的场景看会不会误触发）。

**对照 v2 的必要性判定**：
- ✅ **吸收：三重验证收录门槛（高必要性）**。v2 阶段3 的 schema 有"适用边界/冲突印证"，但缺**条目入库门槛**——什么资格的"规律"才配进库。仓颉三验恰好补缺，且与主库"真信念三门槛"精神同源。防知识库被"正确的废话"灌水，宁缺毋滥。
- ✅ **吸收：反面教训维度（中必要性）**。v2 阶段2 拆解维度缺"失败案例/反面教材"专列——投资书里泡沫破裂、策略失效的教训与正面规律同等重要。
- ⚠️ **不照搬其产物形态**：它的产物是"可触发执行的 skill"，我们的产物是"可引用的证据资产"——定位不同。这反向印证 v2 阶段6 的判断（燕翔两本不转 skill）。
- 📌 它的实践数据印证 v2 成本设计：一本《穷查理宝典》全量蒸馏跑 1.5 小时、token 消耗大——**分级闸门（A/B/C）是必要的省钱设计**。

### 2. Karpathy LLM Wiki（本人 2026-04 idea file）——路线验证 ★★★★☆
**是什么**：Karpathy 本人发布的"知识编译"架构（推文 2.1 万赞 + Gist）：raw/ 只读原料层 → LLM 全权维护的 wiki 层 → schema 层（AGENTS.md 行为契约）；三操作 Ingest / Query / **Lint（健康检查：孤儿页/断链/过时/矛盾）**；Query 产生的优质答案**回写 wiki**。
> 注：与此前审过的第三方仓库"karpathy-claude-wiki"（借名头、非其作品）**不是一回事**，本次引用的是 Karpathy 本人发布的 idea file，社区已有 graphify / llm-wiki-kit / sage-wiki 等实现。

**对照 v2 的必要性判定**：
- ✅ **路线确认（不改方案）**：其核心发现——约 40 万字（≈500 页书，与我们三本书规模同量级）以内，**不需要 RAG/向量库**，LLM 自维护的索引+摘要即可支撑复杂查询。v2 的"检索页+条目ID制"正是这条路线，决策被验证。
- ✅ **吸收：Query 回写机制（中必要性）**。后续报告/投委会流程引用书籍条目时产生的验证结论，应回写条目"印证"字段——知识库因使用而增值。v2 schema 已有该字段，补一条**运营规则**即可。
- 📌 Lint 健康检查：v2 阶段5 QA 是一次性的；可选补"建成后跑一次 Lint 式体检"（孤儿条目/断锚点/矛盾条目），不必常设。**低优先级**。

### 3. books-for-agents（danpalmieri）——schema 参照 ★★★☆☆
**是什么**：结构化书籍摘要知识库 + MCP 服务，schema 五段：ideas / frameworks / quotes / **connections（跨书关联）** / **when-to-use（何时用）**。社区用 agent 捐 token 共建。

**对照 v2 的必要性判定**：
- ✅ schema 互相印证：when-to-use ≈ v2"适用边界"、connections ≈ v2"跨书对照矩阵"——独立同构，说明这两字段是行业共识。
- ⚠️ MCP 服务化**不引入**：我们的库是本地文件，投委会各会话直接读文件/检索页即可，加 MCP 服务层是过度工程。

### 4. SpineDigest（oomol-lab）——图谱可视化 ★★☆☆☆
**是什么**：多阶段管线逐章提取 → 知识图谱串联 → 多 AI 角色"答辩式"对抗生成摘要（防遗漏），配 Inkora 阅读器（章节拓扑图+知识图谱）。

**对照 v2 的必要性判定**：
- ⚠️ "答辩式对抗摘要"防遗漏效果好但 token 成本翻倍——我们的页码锚点回查+抽检 QA 已覆盖漏检风险，对抗式 ROI 不划算。**不引入**。
- 知识图谱可视化：检索页 v2 已有主题/年代索引，图谱视图可作未来增强项，非必需。**暂不做**。

### 5. 通用 RAG 实践（chunking/评估/RAGAS）★★☆☆☆
**对照 v2 的必要性判定**：
- 我们不做向量库，chunking 经验仅微弱相关（阶段0 切块保留结构边界+章/页元数据，v2 已含）。
- 可选借鉴"golden set"概念：阶段5 建一个 10 问测试集验证检索页好用。**低优先级，可并入阶段5 验收**。

### 6. 得到"每天听本书"（商业对照）★☆☆☆☆
面向消遣型消费者的 30 分钟音频+金句形态，**无出处锚点、无边界标注、无数据时效**——正是"可引用证据资产"的反面形态。仅作反面参照，说明 v2 坚持页码锚点+数据截止的必要性。

## 建议吸收项汇总（待拍板）

| # | 增量 | 来源 | 落点 | 优先级 |
|---|---|---|---|---|
| 1 | **三重验证收录门槛**（独立场景≥2 + 预测力 + 非常识，预期通过率 25–50%） | 仓颉.Skill | 主库阶段3 规律条目化 | **高** |
| 2 | **反面教训/失败案例**作为拆解与条目的固定维度 | 仓颉.Skill 五Agent | 主库阶段2+阶段3 schema | 中 |
| 3 | **Query 回写运营规则**（报告引用产生的验证结论回写条目"印证"字段） | Karpathy LLM Wiki | 主库阶段3 schema + 调用接口说明 | 中 |
| 4 | 建成后跑一次 Lint 式体检 + 阶段5 附 10 问测试集 | Karpathy / RAG 实践 | 主库阶段5 验收 | 低（可并入） |

**明确不引入**：MCP 服务化（过度工程）、答辩式对抗摘要（成本翻倍）、知识图谱可视化（暂缓）、RAG/向量库（规模不需要，被 Karpathy 案例反向验证）。
